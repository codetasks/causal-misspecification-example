Two factors, one control decision

To estimate a factor's causal loading you have to decide whether the other factor belongs in the regression. The same control can be required or forbidden, and the regression output looks identical either way. Only the causal graph settles it.

A companion to the one factor notes on Causal Factor Analysis is a Necessary Condition for Investment Efficiency (Lopez de Prado, Lipton, Zoonekynd, 2025). Every number is verified two ways: closed form algebra and Monte Carlo simulation at seed 42 (n up to 2 million). The estimation section is verified by a five fold cross fitted DML run.

The one factor note made a single point: the regression slope of a return on a factor is a causal loading only if nothing else moves both the factor and the return. Add a second factor and the question sharpens into a decision you make on every line of a factor model, usually without noticing. Does the second factor belong in the regression for the first one's loading? The honest answer is that it depends entirely on the second factor's causal role, and four roles give four different answers. As a confounder it must be included. As a collider it must be excluded. As a mediator it changes which effect you are even measuring. As a plain predictor of the return it is optional and only sharpens the estimate. This note works through all four, lets you flip between the two hardest ones and watch the verdict invert, and shows the structural equation, the causal target, and the misspecified regression for each.

One structure is deliberately left out. A latent driver that moves both factors but never touches the return is not a source of bias, only of correlation between the regressors. That benign case has its own section near the end, and it is the reason the confounding in this note always comes from a variable that reaches the return, never from a hidden common cause of the factors alone.

Seeing versus doing, with a second factor

Write X for the return and F2 for the factor whose loading you want. There are two quantities a regression could be after, and they are not the same number.

Seeing: E[X | F2 = f]

observational, what OLS targets

The average return among the periods where the factor happened to read f. It mixes the factor's own effect with whatever else tends to travel with the factor. This is the conditional expectation a regression of X on F2 converges to.

Doing: E[X | do(F2 = f)]

interventional, the causal loading

The average return if you set the exposure to f by intervention and held everything upstream fixed. The loading is the slope of this in f. This is the number that belongs in a portfolio optimizer, because the optimizer chooses exposures, it does not merely observe them.

The two agree only when no third variable creates a backdoor path between F2 and X. The whole job of the second factor F1 is to either open such a path, block one, or sit on the path you are trying to measure. The estimand throughout is the causal loading, the slope of the do expression:

E[X | do(F2=f)] = β f,    so ∂/∂f = β the target

F1 as a confounder: the control you must keep

Suppose the second factor is a common cause of the first factor and the return. A macro regime that drives a value tilt and independently drives realized returns is the textbook case. In structural form, with all idiosyncratic terms independent and mean zero:

F1 = η1,   F2 = aF1 + η2,   X = βF2 + cF1 + ε

The causal loading of X on F2 is β. There is one backdoor path, F2 ← F1 → X, and it is open whenever F1 is left out. Regress X on F2 alone and the slope converges not to β but to

Where the bias term comes from (omitted variable formula)

Substitute the factor equation into the return: X = β(aF1+η2) + cF1 + ε = (βa+c)F1 + βη2 + ε. With unit variances for F1 and η2, Cov(F2, X) = a(βa+c) + β and Var(F2) = a2+1. The single regressor slope is their ratio, which simplifies to β + ac/(a2+1). The bias is the classic omitted coefficient times the regression of the omitted control on the included one: here c times a/(a2+1).

The fix is the backdoor adjustment. Setting F2 by intervention deletes its equation; the remaining path through F1 is closed once F1 is in the regression, because F1 is then held fixed. Including it returns the exact coefficient, β. At β = 1.0, a = 0.8, c = 0.7:

omit F1 (backdoor open)1.341biased by a·c/(a²+1) = 0.341
control F1 (backdoor closed)1.000the causal loading

Monte Carlo at seed 42 (n = 2 million) returns 1.341 omitting and 1.000 controlling, matching the closed form. Here the omitted control belongs in the model.

F1 as a collider: the control you must drop

Now flip the arrows. Suppose the second factor is a common effect of the first factor and the return rather than a cause. An analyst rating that rises both with the factor exposure and with the realized return is the canonical example: it is downstream of both, not upstream. In structural form:

F2 = η2,   X = βF2 + ε,   F1 = aF2 + cX + η1

Here there is no backdoor at all: F2 is exogenous, so regressing X on F2 alone recovers β directly. The trap is the opposite of before. Adding F1 as a control conditions on a common effect of F2 and X, which opens a non causal path between them and biases the slope.

Why conditioning on a collider induces a spurious slope

A collider is a node with two arrows into it. F1 ← F2 and F1 ← X meet at F1, so the path F2 → F1 ← X is blocked by default. Conditioning on the collider unblocks it: once you know F1, a high F2 implies a low X is needed to explain the same F1, manufacturing a negative association that was never causal. Algebraically the two regressor OLS coefficient on F2 is (Vf₁·β − p·Cov(F1,X)) / det, with p = a+cβ, det = c2+1, which is not β unless a = c = 0.

omit F1 (collider closed)1.000the causal loading
control F1 (collider opened)0.296biased toward zero and beyond

Monte Carlo at seed 42 returns 1.000 omitting and 0.296 controlling, matching the closed form. Here the added control wrecks an estimate that was already correct.

the point

Compare the two tables. The confounder case is fixed by adding F1; the collider case is broken by adding F1. The action is identical, the data can be made to show the same correlations, and the regression diagnostics (fit, t statistics, residuals) look healthy in both. What separates them is the direction of the arrows touching F1, which lives in the causal model, not in the sample.

Two more roles: mediator and neutral predictor

Confounder and collider are the two cases the widget toggles because they invert. Two more complete the map, and both are common in factor work.

mediator · controlling changes the estimand

Suppose the chain is F2 → F1 → X: the factor moves a second factor, which in turn moves the return. With F1 = 0.7F2 + noise and X = 0.6F2 + 0.5F1 + noise, regressing X on F2 alone recovers the total effect 0.6 + 0.5·0.7 = 0.95 (simulated 0.950). Add F1 as a control and you get the direct effect only, 0.600, because conditioning on the mediator removes the part of F2's effect that flows through it. Neither is wrong, but they answer different questions. If the optimizer chooses total exposure to F2, the total effect is the loading you want, and controlling for the mediator is the bad move. verified

neutral predictor · optional, sharpens the estimate

Suppose F1 affects the return but is unrelated to F2: X = βF2 + 0.8F1 + noise with F1 independent of F2. Now F1 is neither a confounder nor a collider, so leaving it in or out gives the same unbiased loading on F2 (1.000 either way). Including it is still worth doing: it soaks up return variance that would otherwise sit in the residual, shrinking the standard error on β by a factor of √(1 + 0.82) = 1.28 in this example (simulated SE ratio 1.28). This is the one kind of extra control that is free: it cannot bias the loading and it tightens the interval. verified

A hidden driver that never touches the return is harmless

It is tempting to treat any latent common driver of two factors as a threat. It is not, as long as the driver does not also move the return. Let an unobserved U (a macro regime, a crowding wave) drive both factors but leave the return equation alone:

F1 = γ1U + η1,   F2 = γ2U + η2,   X = β1F1 + β2F2 + ε (no U term in X)

Because U reaches X only through the two factors, and the factors are themselves the regressors, there is no open backdoor. The multivariate regression of X on (F1, F2) recovers the true loadings exactly. At γ = (0.8, 0.4), β = (1.0, 0.5), the OLS estimate is (1.000, 0.500) even though U makes the two factors correlated, with corr(F1, F2) = 0.23. verified

The only cost of U here is collinearity between the regressors, which inflates the variance of the loadings (the standard variance inflation factor), but leaves them unbiased. This is exactly the case this note leaves out of the confounding story: a driver of the factors that stops short of the return is a precision problem, not an identification problem. Confounding requires a path into the return. That is why every biased case above involves a variable that reaches X.

The full map of good and bad controls

Five structures, one decision each. The role is a property of the causal graph; the regression fit is the same across the first four rows and cannot tell them apart.

Estimation: recovering the loading with controls

In practice the confounder is not handed to you as a single clean variable. You have the factor F2, the return X, and a set of measured controls W (other factors, macro and liquidity series) that you hope blocks every backdoor into F2. The estimand is the loading β in a partially linear model that lets the controls enter flexibly:

X = βF2 + g(W) + ε,     F2 = m(W) + V,  E[V|W] = 0

The debiased (Robinson partialling out) estimator residualizes the factor and the return on the controls, then regresses one residual on the other. The Neyman orthogonal moment is

ψ = V(X − r(W) − βV),   β̂ = E[V(X − r(W))] / E[V2] verified
V = F2 − m(W) the factor residual, r(W) = E[X|W]; orthogonal to first order error in the nuisances m, r

The estimator uses K fold cross fitting (K = 5, repeated and median pooled): the nuisances m and r are fit on held out folds so their estimation error does not contaminate the moment. Without cross fitting the flexible machine learning error reinstates a root n bias that voids the confidence interval. The variance is the orthogonal score sandwich. When F2 is nearly explained by the controls (little independent variation left in V) the variance inflates, the continuous treatment analogue of an overlap failure: the data carry little information to separate the loading from the controls, and the method reports that as a wide interval rather than a false precision.

The dividing line: estimation does not manufacture identification

Whether this recovers the causal loading depends entirely on whether W actually contains the confounder. Cross fitted DML on the confounder data generating process (seed 42, n = 40,000, gradient boosted nuisances), estimating the loading on F2 with the true loading equal to 1.0:

the honest caveat

Debiased machine learning gives valid inference on the loading only when the control set satisfies the backdoor condition that identification requires. If the true confounder is unmeasured and the controls are insufficient, DML is consistent for the partialled out projection, not for the causal loading: the orthogonal machinery makes the wrong number precise, with a tight and misleading interval. Cross fitting fixes the bias from flexible nuisances; it does nothing about an open backdoor. That is why an observational loading needs a sensitivity analysis, how strong an unmeasured confounder would have to be to overturn the sign or the ranking, before it drives a portfolio.

Why it matters for the portfolio

The factor constrained mean variance weights are ω* = V⁻¹ B (B' V⁻¹ B)⁻¹ c', where B is the loading matrix, one column per factor. Feeding in the confounded loading (1.34 instead of 1.0 on F2) corrupts every appearance of B. The optimizer does not merely mis size that one tilt; it mis ranks the factors, because the ratio of a biased loading to a clean one (1.34 / 0.50 = 2.68 against the causal 1.0 / 0.50 = 2.0) tells it the wrong factor is the better buy. The book tilts toward the wrong exposure, and the error is stable only while the confounder behaves as it did in the sample. Getting the loading causally right is what lets the optimizer rank and size factors the way the efficient frontier actually requires.

When the loading is identified

Identified

the do slope equals the regression slope

Every common cause of F2 and X is observed and in the control set; you do not condition on any collider or on a mediator of the effect you want; and the functional form is rich enough (here, linear) that the partialled out slope is the structural one.

Not identified

no sample size fixes it

A common cause of F2 and X is unobserved and unproxied, or a collider sits in the control set, or the estimand is ambiguous between total and direct effect. The regression still returns a tight number; it is just the wrong one.

Common confusions

More controls is safer.
No. Each control is a separate causal decision. Adding a collider or a mediator makes a correct estimate wrong. The kitchen sink regression is not conservative; it is a bet that none of the included variables is a collider or a mediator.
A high R² means the loadings are good.
No. Fit measures prediction, not identification. The collider specification above can have a higher R² than the correct one while returning a loading of 0.30 instead of 1.0.
The regression can tell me whether F1 is a confounder or a collider.
No. The confounder and collider data generating processes can produce the same covariance matrix among F1, F2, X. The direction of the arrows is what differs, and it is not in the second moments the regression sees.
Collinearity is the same problem as confounding.
No. A driver of both factors that does not reach the return makes the factors correlated and the loadings noisy, but not biased. Confounding requires a path into the return. Collinearity is a precision problem; confounding is an identification problem.
Controlling for a variable always reduces bias.
No. It reduces bias for a confounder, introduces bias for a collider, changes the estimand for a mediator, and does neither for a neutral predictor. The sign of the effect of controlling is set by the graph.
